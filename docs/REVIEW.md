# 实现笔记

## 切块前先检查输入

原来的切块代码只根据元素总数 reshape。下面的数组虽然尺寸不对，仍会得到 `(1,49,3072)` 的输出：

```python
encoder.patchify(np.zeros((1, 3, 112, 448), dtype=np.float32))
```

NHWC 输入也有相同问题，因为它与 CHW 的元素总数相等。float64 输入则会让后面的结果不符合课程要求的类型。

现在 `patchify` 会先检查输入是 NumPy 数组、形状为 `[B,3,224,224]`、类型为 float32。形状错误抛出 `ValueError`，数组类型或数据类型错误抛出 `TypeError`。

三个新增测试覆盖了错误尺寸、NHWC、缺少 batch 轴、float64、uint8 和列表输入。加上原有的切块、分头、注意力测试，六项全部通过。

## 切块顺序

切块要经过以下变化：

```text
[B,3,224,224]
→ [B,3,7,32,7,32]
→ [B,7,7,3,32,32]
→ [B,49,3072]
```

中间的 transpose 把同一个方形小块的像素排在一起。直接 reshape 虽然形状相同，取到的像素却不对。

`docs/debug_patch_order.py` 用递增编号的像素作对照：直接 reshape 有 150464 个元素位置不匹配，正式实现为 0。这是专门构造的排错例子，输出保存在 `results/patch_order_debug.txt`。

## 用新输入检查批处理和独立运行

```powershell
python tests/verify_inference.py --output results/extra_validation.json
```

这项检查需要模型权重。脚本用种子 137 生成两张新输入，分别单张计算，再按 `[1,0,1,0]` 批量计算，最大绝对差为 `1.490e-07`。

之后建立一个只放代码、配置和权重的临时项目，不复制 `assets/`。从其他目录调用 `run.py`，处理新生成的 RGB 和灰度图片，检查 ID、形状、float32、有限值和单位长度。命令行与 API 输出的最大差为 `0`。子进程按 UTF-8 运行，避免中文路径下的日志编码问题。

完整输出在 `results/extra_validation.json` 和 `results/extra_validation.txt`。模型与教师参考的误差仍用 `check.py` 判断，八个阶段全部通过，最大输出误差为 `5.662e-07`。

## 几处容易混淆的地方

- K 是四维数组，只交换最后两个轴，不能直接使用二维例子中的 `k.T`。
- 普通线性层使用 `weight.T`，最终 `visual.proj` 已经是 `[768,512]`，直接相乘。
- 第一条残差加回原输入，第二条加回第一次更新后的结果。
- LayerNorm 调整每个 token 的数值分布，最后的单位化调整输出向量长度。

预处理、参数加载、数值辅助函数和教师检查脚本使用课程版本。当前检查没有评测分类或检索准确率；后续若改进性能，还需要重新核对精度并测量耗时。
